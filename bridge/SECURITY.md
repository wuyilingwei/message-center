# Security model

## 信任边界

Bridge 群消息、昵称、附件、链接和引用内容全部是不可信输入。群消息不能改变服务配置、扩大项目列表、增加动作权限或关闭审批。`scope` 由本地配置和适配器提供的身份可信度计算，是 Agent 可用权限的上限。

## 身份要求

特权会话默认要求 conversation 和 sender 都是 `verified`。仅从窗口标题、OCR 或可修改昵称推断出的身份必须标为 `display_only`，会被拒绝获得项目权限。设备会话适配器只有在能从受信任的客户端运行时取得稳定会话/成员标识时，才可以产生 `verified`。

## 附件

- 只允许下载当前租约消息列出的附件。
- 源文件必须位于配置的 staging 根目录内，解析符号链接后再次检查边界。
- 默认上限 25 MiB。
- 默认阻止可执行文件、DLL、安装包、快捷方式和常见脚本扩展名。
- 有声明 SHA-256 时必须匹配。
- 下载目录是隔离区；MCP 不提供执行附件的能力。

压缩包仍可能包含恶意内容。生产环境应在解压前增加杀毒/内容消毒服务，并对压缩比、嵌套层数、文件数量和展开后总大小设置硬上限。

## 回复

`reply_message` 只接受消息 ID、租约、幂等键和正文；目标会话来自数据库中的不可变 `replyHandle`，调用者不能指定任意接收人。默认 `dry_run`。实时回复可要求 Windows 处于离席或锁屏状态；适配器若不支持锁屏发送，会拒绝操作。

## 明确不包含

- 任意命令执行或把聊天文本传给 Shell。
- Cookie、令牌、会话密钥、聊天数据库或登录凭证提取。
- 进程空洞、反射加载、证书校验绕过或流量中间人解密。
- 反病毒规避、隐藏持久化、键盘记录、截图采集或远程桌面控制。
- 向非原始会话任意群发。

设备连接器在受控的越狱设备上使用版本固定的运行时观测与调用，以复用用户已登录会话；它只暴露别名化消息、受限回复和文件操作，不导出认证材料。客户端版本变化后必须重新验证，失败时应关闭对应能力。

## 生产部署

- MCP HTTP 端点保持回环绑定，通过现有零信任网关或 VPN 接入。
- 为编排器使用独立服务身份和短周期凭据。
- 项目执行器使用低权限操作系统账户、独立工作区和网络出口白名单。
- 把 SQLite 与审计日志纳入备份和访问控制；日志不记录消息正文。
- 生产部署前将 Node 内置 SQLite 替换或锁定为经过组织验证的持久层，因为当前 Node 24 仍将该模块标记为实验性。
